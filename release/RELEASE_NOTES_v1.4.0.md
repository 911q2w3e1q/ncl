# NCL 1.4.0 — AI 报错分析

这次给启动器塞进了一个 AI：游戏崩溃时自动分析原因、给出可一键应用的解决方案，点「帮我解决」自动改配置并重启游戏验证。

> v1.0.0（仅 Windows）/ v1.1.0 / v1.2.0 / v1.3.0 Release 仍保留，不影响老用户。从 1.3.0 升级直接下载本版覆盖即可，也可在启动器内「设置 → 启动器 → 检查更新」一键完成。

## 新增：AI 报错分析

### 先配置一下（只需一次）

设置 → 启动器 → **AI 报错分析**：

| 项 | 说明 |
|---|---|
| 启用 AI 分析 | 总开关 |
| 崩溃时自动分析 | 游戏异常退出后自动弹出分析结果；关掉就手动点「分析报错」 |
| API 地址 | 兼容任何 OpenAI 格式接口，如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、`https://open.bigmodel.cn/api/paas/v4` |
| API Key | **只保存在本机设置文件，不会上传到任何第三方**（除了你自己指定的模型服务） |
| 模型 | 如 `gpt-4o-mini`、`deepseek-chat`、`glm-4-flash` |
| 测试连接 | 一键验证地址 / Key / 模型是否可用 |

### 怎么用

**方式一（自动）**：游戏异常退出（崩溃报告、异常栈、内存溢出、非 0 退出码）时，启动器自动收集现场并调用 AI 分析，直接弹出结果面板。

**方式二（手动）**：运行日志区点 **「🩺 分析报错」**，随时让 AI 排查当前这次的报错。

### 分析结果面板

- **核心原因**：一句话概括，带「把握较大 / 把握一般 / 把握较小」置信度标签
- **可能的原因**：从崩溃报告与日志里抽出的具体原因，逐条展开说明
- **解决办法**：每个方案带风险等级（低 / 中 / 高）和说明

### 「帮我解决」一键修复

点任一方案的 **「帮我解决」**，启动器会：

1. 备份当前设置（存到启动器数据目录的 `ai-backups/`）
2. 自动应用该方案对应的配置修改
3. **用新配置自动重启游戏**，你可以直接看是否还崩

可自动执行的修改（由 AI 判断选用）：

| 动作 | 用途 |
|---|---|
| 调整内存上限 | OutOfMemoryError、堆内存不足 |
| 追加 / 移除 JVM 参数 | G1GC、模块化限制、启动参数不兼容 |
| 更换 Java 路径 | UnsupportedClassVersionError、Java 版本过低 |
| 调整窗口宽高 / 全屏 | 分辨率相关崩溃、窗口无法创建 |
| 开关版本隔离 | 模组与世界互相污染 |
| 设置服务器地址 | 进不去服务器 |
| 写文件（限游戏目录内） | 生成修复脚本、启动脚本等 |

> 安全约束：写文件只允许游戏目录内的相对路径，绝对路径与 `..` 逃逸会被拒绝；非法数值（如内存设成 999999）直接驳回并告诉你原因；每次修改前自动备份，出问题可在设置里回滚。

## 使用方法

**Windows**
1. 解压 zip，得到 `NCL.exe` 和 `engine` 文件夹（保持它们在一起）
2. 双击 `NCL.exe` 即可，无需安装

**Linux**
1. `tar -xzf NCL-1.4.0-linux-x64.tar.gz`
2. 进入目录执行 `./NCL.sh`

**macOS**
1. 解压 zip 得到 `NCL.app`
2. 首次打开：右键（或 Ctrl+点击）→ 打开，在弹窗里再点「打开」
3. 之后可拖入「应用程序」文件夹正常使用

## 数据位置

| 平台 | 游戏数据 | 启动器数据 |
|---|---|---|
| Windows | 启动器旁 `.minecraft` | `%APPDATA%\ncl` |
| Linux | 启动器旁 `.minecraft` | `~/.config/ncl` |
| macOS | `~/Library/Application Support/ncl/minecraft` | `~/Library/Application Support/ncl` |

AI 配置在启动器设置里；自动修复的备份在启动器数据目录的 `ai-backups/` 下。

## 已知限制

- **需要自备模型 API Key**，本启动器不内置免费额度。Key 只存本机，仅在你点分析时才发往你填的接口。
- 分析质量取决于所选模型；小模型可能只给出笼统结论，此时建议参考面板里的「可能的原因」自行排查。
- 崩溃现场采集依赖 `crash-reports` 目录与运行日志；若是启动器层面就失败（如 Java 起不来），信息会少一些。
- 「帮我解决」只能改启动器能管理的配置（内存 / JVM 参数 / Java / 分辨率 / 隔离 / 服务器地址 / 游戏目录内文件）。需要换 mod、删文件、装 Java 等更重的操作仍需手动处理。
